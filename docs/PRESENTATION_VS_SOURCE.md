# 2023년 최종 발표 ↔ 실제 보관 소스

**근거**: `4조 캡스톤디자인 압사 방지 CCTV 최종.pptx` (세이프워치, 캡스톤디자인 4조), `4조 캡스톤디자인 압사 방지 CCTV 6월1주차.pptx`, 2023 보관 Python·HTML·PHP·SQL. 이 비교표는 **2026년에 작성된 문서**이며 당시 소스코드가 아닙니다.

## 발표와 원본 양쪽에 근거가 있는 핵심 기능

- 카메라 영상 수집: `stream.py`의 Picamera2/MJPEG, `main.py`의 영상 프레임 추출.
- TensorFlow/TFLite 기반 사람 탐지: `count_objects.py`의 이미 변환된 모델 불러오기·추론. 학습·모델 구조 변경은 이 실행 코드에 없음. 모델 변환 후 재학습 또는 수정하지 않았다는 사용자 확인을 우선함.
- 고정된 구역 면적과 인원수: `configs.ini`의 `total_area=300`을 읽어 `people_num / total_area` 연산. **실시간 면적 추정, 보행면적 동적 계산 또는 장애물 면적 차감 기능은 원본에서 실행되지 않음.**
- 이미지: `before.jpg`와 `after.jpg`는 각각 같은 경로로 `cv2.imwrite`하여 새 촬영·추론 결과로 **직접 덮어쓰기**. 웹 `image.php`는 `/tensorflow/after.jpg`를 2초마다 재요청하며 캐시 무효화 시간 쿼리 사용.
- DB 기록 및 Nginx/PHP/AJAX, 밀집도·변화율 그래프, Google 지도, 경고음·Twilio SMS 호출 코드.

## 2026-10-31 사용자 확인: 실제 최종 구현의 동작

사용자는 최종 코드에서 **사람 수 기준으로 위험 단계를 판정**했으며, 그래프는 **백분율 변화율(%)**, 실제 위험 SMS는 **`alarm.py`**, 인식 결과의 DB 저장 주기는 **10초**였다고 확인했습니다. 이는 새로 추정한 기능이 아니라 당시 최종 구현에 관한 당사자의 직접 확인입니다. 현 보관 소스와 다른 부분은 복원 코드를 만들어 덮어쓰지 않고 아래에 명시합니다.

## 최종 발표·사용자 확인과 보관 코드의 위험 판정 차이 — 원본 수정하지 않음

| 인원 수 | 최종 발표 및 사용자 확인한 최종 구현 | `main.py` 보관 사본(면적=300) |
| ---: | --- | --- |
| 1~2명 | 안전 | 안전 |
| 3~4명 | 경고 | 안전 |
| 5명 이상 | 위험 | 5명에서는 안전; 임계값은 `people_num/300`의 2, 4 |

최종 발표 자료는 **안전 1~2명 / 경고 3~4명 / 위험 5명 이상**을 명확히 기재하며, 사용자는 **최종 코드에서 인원 수 기준 판정을 실제로 구현했다**고 확인했습니다. 그러나 보관 사본 `main.py`의 `get_alert_level`은 `density = people_num / total_area`로 나눈 뒤 `density <= 2`이면 안전, `2 < density < 4`이면 경고, 그 외 위험을 반환합니다. **최종판 코드 원문 자체는 현재 보관 사본에서 확인되지 않습니다.**

**결론**: 최종 위험 판단은 발표와 사용자 확인이 일치하는 **인원 수 기준**으로 확정합니다. 다만 현재의 `main.py`는 다른 버전의 보관 소스이므로 이를 몰래 변경하지 않습니다. 나중에 동작 재현 코드가 필요하다면 **원본과 분리된 수정·복원본**으로 표시해야 합니다.

## 원본의 데이터·경고·모델 세부

- **경고·문자 발송**: 사용자는 **실제 최종 SMS 발송 경로가 `alarm.py`**였다고 확인. 보관 `alarm.py`는 10초마다 최신 DB 위험 수준을 조회하고, 계속 위험이면 매 주기 WAV/Twilio 호출. 브라우저 `maininfo.html`의 `/send_sms` 호출도 보관 소스에 존재하지만 최종 문자 발송 경로로 취급하지 않음. 300초 cooldown/상태 진입 알림은 2026년 생성 코드였으며 이 `main`에서 제외.
- **DB·그래프**: 사용자는 **최종 변화 그래프가 백분율 변화율(%)**이었다고 확인. 이는 보관 `schema_legacy_percent.sql`의 이전값 대비 `%` 계산과 일치하지만 개인 최종보고서의 절대 차이 SQL과는 상충. 0으로 나누는 상황에 대한 명시적 방어는 보관 SQL에서 확인되지 않음. 2026년 만든 `LAG` 기반 VIEW·`people_count` 컬럼·0 처리 보호는 제외.
- **TFLite 추론**: 원본은 `load_model`에서 Interpreter를 생성하고 추론. 별도의 Interpreter 캐시·최적화는 2026년 재구성 추가였기에 제외.
- **이미지**: 원본은 직접 `cv2.imwrite`로 덮어씀. 임시 JPG → 원자적 rename 방식은 2026년 추가여서 제외.
- **장애물 / IoU**: 중간 발표에는 장애물 분류 학습과 IoU 추가 계획이 있으나, 확인된 최종 `count_objects.py`에서는 장애물 모델 탐지 호출이 주석 처리되어 있음. 이 기능을 완성했다고 단정하지 않으며 새로 구현하지 않음.

**검증 수준**: 소스 함수·SQL·웹 파일과 발표 슬라이드 텍스트 근거의 대조입니다. 2023년 사진·영상에서는 웹·DB·카메라 통합 시연이 확인됐고, 추가 제공된 휴대전화 화면에서 **Twilio 위험 SMS 실제 수신**도 확인됐습니다. 그러나 카메라가 실제 위험을 자동 감지해 발송했는지, 현재 환경에서 전체 시스템이 실행되는지는 미확인입니다. [SMS 및 추가 자산 증거](ARTIFACT_AND_SMS_EVIDENCE.md).

## 추가 1차 자료: 2023-06-05 개인 최종보고서와 공개용 보관본 차이

상세 비교는 [대화·최종보고서 재대조](2023_CONVERSATIONS_AND_REPORT_AUDIT.md)를 참고.

- **처리 간격**: 사용자는 최종 인식·DB 저장 주기가 **10초**였다고 확인. 최종보고서의 `configs.ini`도 `delay=10`이지만 현재 보관 소스는 `delay=15`. 보관 설정은 다른 시점의 사본으로 구분하며 파일은 수정하지 않음.
- **면적 계산 함수**: 보고서 `get_alert_level(total_area, people_num, obstacle_area)`는 `obstacle_area=0`을 전달. 보관 소스 `get_alert_level(total_area, people_num)`은 이를 생략. **실제 장애물 자동 차감은 없는 것**으로 양쪽 자료가 일치.
- **변화율 정의**: 사용자가 최종 그래프는 **백분율(%)**이라고 확인. 현재 Git SQL도 이전값 대비 `%`이지만, 보고서 29쪽 SQL은 밀집도 `현재 - 이전`의 **절대 차이**이며 보고서에는 %에서 차이로 바꿨다는 설명도 남음. **당시 최종 동작은 사용자 확인을 우선**하되, 최종 실행 DB에 적용된 SQL 파일 버전은 별도 로그가 없어 검증하지 못함.
- **현장 검증 범위**: 개인 최종보고서 31–33쪽은 야외 시험에서 경고/위험 단계 미도달, 먼 거리 인식률 저하, 마네킹 오인식 등을 기록. SMS의 실제 수신 사진과 함께 보더라도 실제 군중 위험 자동 경보의 통합 성공까지 입증하지 않음.

최종 발표의 1~2명/3~4명/5명 이상 기준은 그대로 유지합니다. **보관 원본 `main.py`를 임의 수정하여 발표와 일치하는 코드처럼 보이게 하지 않습니다.**
