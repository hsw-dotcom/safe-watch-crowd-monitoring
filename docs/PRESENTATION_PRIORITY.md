# 2023 최종 발표자료 우선 복원 기준

## 근거 우선순위
1. **4조 캡스톤디자인 압사 방지 CCTV 최종.pptx** (4조 Safe Watch 최종 발표)
2. **2023년 4조 프로젝트 실제 보관 Python/SQL/HTML/PHP 코드** (GitHub `archive/pre-dedup-20261031`)
3. **4조 캡스톤디자인 압사 방지 CCTV 6월1주차.pptx** (중간 단계; 예정과 최종 구현 구분)
4. 2023년 당시 질문·답변 및 2026년 사용자 명시적 정정
5. 복원 편의를 위한 신규 구조·검증 코드 (당시 구현으로 간주하지 않음)

2023년 졸음운전 감지 카메라(3조), 라인트레이서 등 다른 프로젝트 자료는 제외합니다.

## 발표자료와 보관 소스의 불일치
- **최종 발표의 시연 단계**: 1~2명 안전, 3~4명 경고, 5명 이상 위험. 감지 0명도 안전으로 처리.
- **보관 원본 main.py**: 인원 수를 설정 면적으로 나눈 `density`를 2, 4와 비교. 이것은 최종 발표와 모순되어 `risk.py`의 경보 판단만 **인원 수 기준으로 수정**했습니다.
- **면적 처리**: 원본 `configs.ini`의 `total_area=300`이 고정값이며, 프로그램이 영상에서 면적을 재계산하지 않았습니다. `density=people_count/300` 계산과 **위험 단계의 인원수 판단은 별개**입니다.
- **모델**: 추출·TFLite 변환된 파일을 읽어 인식하며, 그 이후 모델 자체를 재학습·수정하지 않았습니다. 인식 결과 이미지는 OpenCV로 그려 저장했으며 이는 모델 수정과 다릅니다.
- **이미지 파일**: `before.jpg`, `after.jpg` 파일명을 재사용하며 `cv2.imwrite`로 직접 덮어씁니다. 별도 버전 이미지나 임시 파일 교체를 실제 구현이라고 주장하지 않습니다.
- **변화율의 0 나눗셈**: 원본 SQL은 직전 행이 없는 경우만 처리하며, 직전 밀집도가 0인 경우를 특별히 처리하지 않았습니다. 복원 SQL은 이 계산 구조를 보존합니다. DB 엔진에 따라 결과 `NULL` 또는 경고가 발생할 수 있으므로 데이터 처리의 한계로 기록합니다.
- **경보 반복**: 원본 `alarm.py`는 위험 상태에서 **10초 주기로 경고/문자 전송을 재시도**했고 300초 간격 제한은 없었습니다. 복원본은 원본 반복 로직을 되살렸으나 의도치 않은 실제 SMS 발송을 피하려고 `SAFEWATCH_ENABLE_SMS=0`을 기본값으로 둡니다.

## 임의 확장하지 않은 부분
- 장애물 모델은 중간 발표에 17종 학습 사례가 있으나 최종 보관 코드에서는 실행이 비활성입니다. 장애물 면적을 인식해 빼거나 IoU를 적용하지 않습니다.
- 임의 위험 예측, 인원 추적, 얼굴 식별, 모델 재훈련 등의 알고리즘은 없습니다.
- 하드웨어 없는 `--dry-run`, 웹 `?demo=1`, 단위테스트, API 병합, 접근정보 환경변수 처리는 **현대 복원·검증용**이지 당시 구현을 증명하는 코드가 아닙니다.

## 복원 불확실성
최종 발표의 사람 수 단계와 보관 코드의 면적 비율 경보가 왜 달랐는지는 확인되지 않았습니다. 최종 발표를 우선한다는 사용자 지시에 따라 경보 기준만 변경했고, 보관 원본 코드는 별도 브랜치에서 변경하지 않았습니다.
