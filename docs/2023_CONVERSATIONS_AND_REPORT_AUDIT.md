## 2026-10-31 최종 동작 사용자 확인 (보관 파일과 분리)

1. **위험 판정:** 최종 코드에서는 사람 **인원 수**로 위험 단계를 판정. 최종 발표의 1~2명 안전 / 3~4명 경고 / 5명 이상 위험과 일치. 공개 보관 `main.py`는 밀집도 수치 기준으로 동작하므로 최종 버전이 아닌 다른 사본. 최종 구현된 해당 코드 자체는 미확보.
2. **변화 그래프:** 최종 표시·계산은 이전 측정값 대비 **백분율 변화율(%)**. 공개 보관 SQL은 이에 부합하며 개인 최종보고서에 기재된 절대 차이 SQL은 다른 버전/문서상 불일치로 남김. 최종 실행 SQL 파일의 바이트 대조는 미실시.
3. **문자 발송:** 실제 최종 위험 SMS 발송은 **라즈베리파이 `alarm.py`**. 보관 `maininfo.html`에 `/send_sms` 경로가 있더라도 최종 발송 구현으로 주장하지 않음.
4. **측정 주기:** 최종 사람 인식 및 DB 저장은 **10초 주기**. 2023 개인 최종보고서의 `delay=10`과 부합. 공개 Git `configs.ini`의 `delay=15`는 남아 있는 다른 버전의 파일.

이 네 항목은 **사용자의 직접 확인에 따른 최종 동작 설명**이며, 복구되지 않은 최종 소스의 정확한 문장이나 실제 실행 로그를 확보했다는 의미가 아닙니다. 사용자 요청에 따라 코드·SQL·설정·테스트 파일을 수정하지 않음.

## 새로 확인한 버전 불일치 (원본은 수정하지 않음)

### A. 분석 주기 10초 대 15초

- **2023-06-05 개인 최종보고서 9쪽**에 인용된 `configs.ini`: `delay = 10`, `total_area = 300`. 같은 보고서 21–22쪽에서 DB 그래프의 새 측정값 간격을 약 10초로 설명.
- **현재 Git 보관 소스** `src/python/configs.ini`: `delay = 15`, `total_area = 300`.
- `main.py`의 `time.sleep(delay_time)`은 보관 원본 자체의 호출이고, 보고서에는 별도 `wait_time` 계산 문구가 있음. `wait_time`을 그대로 sleep에 사용했다고 단정하지 않음.
- **최종 실제 인식·DB 저장 주기는 10초로 사용자가 확인함.** 이 사실과 별개로 보관 `configs.ini`의 값은 15초이며 실제 최종 적용된 파일과 다를 수 있음. **보관 설정 원문은 변경하지 않고 두 값을 버전 차이로 기록**.
- `image.php`의 **2초 이미지 재조회**, `maininfo.html`의 **10초 전체 페이지 갱신**, 차트 코드의 **1초 조회**, `alarm.py`의 **10초 위험 확인**은 서로 다른 주기이며 혼동하지 않음.

### B. 장애물 면적 코드의 함수 형태

- **보고서 8–9쪽**의 `main.py`: `get_alert_level(total_area, people_num, obstacle_area)`; 계산은 `people_num / (total_area - obstacle_area)`. 그러나 실제 호출 시 **`obstacle_area=0`을 고정 전달**.
- **현재 Git 보관 소스**: `get_alert_level(total_area, people_num)`, `people_num / total_area`. 즉 실제 전달값이 0인 경로에서만 결과가 같음.
- 양쪽 모두 실시간 장애물 차감이 구현됐다는 증거는 아님. 보고서 6쪽과 31쪽에 **17종 장애물 모델 학습 후 정확도·크기·Raspberry Pi 처리 제약으로 실제 탑재를 제외**했다고 명시됨.
- 보고서의 `get_obstacle_area`는 CSV 파일을 열기 위한 불완전 함수로 제시되지만 최종 계산 경로에 연결되지 않음. CSV·장애물 모델 코드를 새로 만들지 않음.

### C. 변화율 SQL의 의미: %와 밀집도 차이

- **현재 보관 SQL** `database/schema_legacy_percent.sql`: `(current - previous) / previous * 100` — 이전값 대비 비율(%).
- **개인 최종보고서 21–22쪽**: 차트를 비율(%)에서 밀집도의 **절대 차이**로 수정했다고 서술.
- **보고서 29쪽의 VIEW 정의**: `current.crowd_density - previous.crowd_density`를 `change_rate`에 저장; 분모 없음.
- 하지만 **보고서 25–26쪽 `change.html`의 표시 라벨**은 여전히 `밀집도 변화율 (%p)`로 기재되어 있음. 표기와 SQL의 의미가 충돌함.
- **최종 그래프의 동작은 백분율(%)이라고 사용자가 확인함.** 이는 현재 보관 SQL의 `%` 연산과 부합. 다만 최종 DB에 적용됐던 SQL 파일의 개별 이력/실행 로그는 미확보. 보관 `schema_legacy_percent.sql`을 임의 교체하지 않고 보고서의 절대 차이 SQL도 코드로 추가하지 않음.
- 이전값 0 처리 미구현에 관한 사용자 진술과 일치하는 것은 % 방식의 명시적 방어가 없다는 점. 차이 방식은 나눗셈 자체가 없음.

## 2023년 평가·한계: 성공 범위의 과장 방지

**개인 최종보고서 31–33쪽**:
- 명지대학교 및 기흥역 주변의 야외 환경에서 시험.
- 야외 시험으로 **경고/위험 수준까지 도달하지 못해**, 그 상황에서 SMS·경고음 자동 연동까지 제대로 시험하지 못했다고 명시.
- 약 5m의 인원은 어느 정도 인식했으나 **10m 이상에서는 인식률이 크게 낮아짐**. 이 수치는 정량 벤치마크가 아니라 당시 시험 체감 기록임.
- 옷 입은 마네킹을 사람으로 잘못 인식한 사례와 사람형 조형물 인식 차이를 보고.
- 전체 면적은 고정값을 사용하므로 야외에서 물리적으로 정확한 밀집도 측정이라고 주장할 수 없음.
- **경고음 구현의 성공 진술**과 **실제 위험군중 상황에서의 자동 경보 시험 미완료**는 서로 다른 사실. 둘 다 그대로 기록.
- 보고서와 SMS 사진에 당시 인증번호·사람 얼굴 등 민감정보가 있을 수 있으므로 원본 전문·원본 화면을 공개 저장소에 추가하지 않음.

## '대화에 나온 제안'이지 실제 최종 기능은 아닌 것

- `motion` 설치 및 포트 8081 제안: 확인된 최종 스트리밍은 `Picamera2` + Python MJPEG 포트 8000. `motion` 기능은 추가하지 않음.
- 초기 `video.html`, `get_data.php` 등의 HTML/PHP 예시: 초기 대화의 설계안일 수 있으나 확인된 최종 웹 파일 `index.html`, `image.php`, `maininfo.html`, `density.html`, `change.html`, `map.html` 등으로 갈음. 새 파일 추가하지 않음.
- 장애물 검출을 이용한 면적 보정, IoU 중복 박스 보정: 설계·연구·추가 예정과 실제 완성 상태를 구분.
- 연속적인 밀집도 급증만을 조건으로 **추가 경고**하는 별도 프로그램: 후대 이력서성 기술에서는 언급되지만, 최종 발표·개인 보고서의 확인된 실행 함수/SQL만으로 독립 경고 로직을 입증할 수 없음. **새 구현/완료 단정하지 않음.**
- 2026년 복원본의 `app.py`, 모델 캐싱, `risk.py`, `db.py`, SMS cooldown, 데모 JSON, 데이터 컬럼 추가, systemd 서비스 파일은 2023 보관 원본이 아니므로 `main`에 복귀시키지 않음. **최종판 인원 기준 위험 판정도, 보관 소스의 함수와 다르다는 이유만으로 새로 구현하지 않음.**
